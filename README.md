# IPv6 下载助手

一个面向 Windows 11 x64 的桌面工具，用来查看下载和视频流量实际经过 IPv6、IPv4 还是未知的代理出口，并按平台选择混合保护或严格 IPv6。

开发这个工具，是想在 IPv6 不计费的校园网里尽量减少收费 IPv4 流量，同时保留必要的登录、取链接等连接。目标不是单纯按文件大小分流，而是让支持 IPv6 的流量尽量走 IPv6，让必要的原路径请求有额度、有统计。是否免流取决于所在网络的计费规则，使用时可以对照校园网额度记录。

## 界面上的数据怎么看

主界面按**夸克网盘、Bilibili、Steam、Epic Games、YouTube、其他网站**排列，Bilibili 标识使用大写 **B**。每张服务卡右上角控制接管，下一行的**混合模式**开关独立控制辅助 IPv4；卡片显示各协议累计下载、下载速率、总上传速率、主要服务器及辅助额度。

目前实际平台测试范围仅包括 Bilibili、夸克、Steam，不代表六个平台的所有资源均已验证。

- **IPv6**：助手通过 IPv6 对外连接时中继的数据。
- **IPv4**：助手通过 IPv4 对外连接时中继的数据。
- **未知**：数据交给了本机原有代理等上游路径，助手无法确认其最终出口是 IPv4 还是 IPv6。本机代理地址为 `127.0.0.1`，不等于远端下载走 IPv4。

顶部圆环汇总六个分类的累计下载。三张流量卡分别显示 IPv6、IPv4、未知的下载速度、上传速度、累计下载、累计上传和最近 60 秒下载趋势。IPv6 下载占比按 `IPv6 下载量 ÷（IPv6 + IPv4 + 未知下载量）` 计算，不含上传。

服务标题右侧的总开关与六张服务卡双向联动，显示全部开启、全部关闭或部分开启。右上方保留**使用说明、详细诊断、导出报告、清零流量**，并提供深色 / 浅色主题切换。窗口缩小时自动切换两列或单列，可滚动查看全部服务。清零同时清除累计量、速率和趋势。

v3.1.3 将后台 Clash 状态查询与网络设置修改分开，避免周期查询时把仍开启的服务开关临时画成灰色；实际修改期间仍锁定操作，开关颜色继续表示所选状态。修复切换窗口列数后沿用旧滚动范围、导致末尾出现大块空白的问题。

v3.3.0 将明确的登录、目录和取链接辅助域名归入对应服务：混合保护可走原路径并计入该服务的 IPv4 或未知统计，严格模式也要求辅助请求仅 IPv6。关闭服务时，辅助请求不受“其他网站”开关影响。不写死 CDN 地址、不改变签名链接、不保证 CDN 吞吐，也不代表所有 AList/播放器组合已完成播放验收。

开启服务按中继收发流字节统计。关闭服务后保留累计量，并继续被动监测：

- 夸克、Bilibili、Steam、Epic 独立原生进程按进程归属统计公网连接。
- 浏览器和本机 AList / OpenList / 爆米花通过 Windows DNS 查询完成事件，将**同一进程**的近期地址答案关联到平台。状态明确显示“DNS 关联”，不是逐请求的确定归属，也不是把整个浏览器或全部 AList 存储算成夸克。
- 播放器到本机 AList 的回环流量和私网流量不重复计量。跨进程 DNS、失败查询、共享 IP、加密 DNS、监测开始前已缓存的查询、本机代理等可能导致漏计；未归属部分在覆盖提示中标出，不补零或伪报。
- DNS 关联最多 4096 项，短期窗口 60 秒；已关联的活动连接继续计量，新发现共享地址则停止关联。空闲流记录两分钟回收，最多 20000 项，进程退出 / PID 复用清理，不在每次界面刷新中重新执行 DNS 查询。
- 检测到 TUN 时，应用连接的地址族不能证明最终物理出口，计入未知。ETW / DNS 事件未授权或不可用时显示采集状态，报告附丢失事件数。统计仅覆盖助手运行期间，不代替整机计量或校园网账单。

## IPv6 节点（v3.2.0）

自动连接与节点面板使用相同的系统 DNS / AliDNS 来源；v3.2.2 给系统 DNS 最多350毫秒的优先机会，以保留当前网络的 CDN 调度，系统解析失败、空结果或超过该时间仍可使用公共 DNS。最多三个 IPv6 候选并行建连，成功后取消其余候选。内容自动连接与手动节点均绑定接管前捕获的物理 IPv6 出口。服务关闭时更新 PAC 和原生内核选择组，原生流量不再经过内容中继；最后一个服务关闭时停止接管。已建立连接会在开关切换后关闭，应用需要重连。

v3.3.9 对 `dl-*.quark.cn` 内容域名增加 AliDNS 的当前 IPv6 网段上下文：仅使用绑定物理出口的公网 IPv6，遮去后 80 位，以 `/48` 网段发送，不发送完整设备地址、Cookie 或下载链接。自动解析优先等待该来源最多800毫秒，失败、空结果或超时后沿用原有 IPv6 来源；连接失败时仍可合并来源重试。节点面板标注“AliDNS / 当前 IPv6 网段”。其他服务、夸克辅助接口、原生客户端已有 IPv6 目标与手选节点优先级不变，不改系统 DNS、hosts、签名主机、分片、画质或 IPv4 许可。网段调度结果不等于实际测速结果；已建立的下载不会被后台反复换节点。

原生接管的普通 DNS 与直连 DNS 使用系统配置，不再统一替换为公共 DoH；私有 IPv4、链路本地地址和 IPv6 ULA 网段不进入 TUN。仍有服务开启时，TUN 和 DNS 接管机制仍存在，并不等于退出整个助手；校园网登录是否恢复及实际资源吞吐需要按当前网络验证，不保证某个 CDN 一定更快。

v3.3.6 区分本地网络目标与公网目标，不再把“域名形式的内网地址”当成必须支持 IPv6 的公网网站。开启“其他网站”时，PAC 用系统 DNS 识别普通域名是否指向本地网络；关闭“其他网站”时，普通域名直接沿用原代理路径，不额外执行同步 DNS，避免影响未接管网站的响应。缓存 PAC 仍指向助手时，中继会用实际地址检查本地目标，私网建连失败不再转交外部代理。这不是校园域名白名单，也不代表全部 TUN 性能问题已经修复。

“此下载域名未查到 IPv6”指当前资源服务器的解析结果，不代表本机没有 IPv6。不同的 `pds` / `drive` 下载域名、不同视频 CDN 可以有不同的地址族支持；不能将另一个域名的节点直接套用到当前带签名资源。没有可用 AAAA 时继续明确报错，不回退 IPv4，也不声称自动连接最快等于实际下载速度最快。

主界面 **IPv6 节点** 打开节点面板。面板提供夸克网盘、Bilibili、Steam 和自定义域名四个快速入口；选择当前实际内容域名后点击刷新，查询系统 DNS 和 AliDNS 返回的公网 AAAA。候选按 DNS 有效期保留，系统解析结果因无法取得 TTL 仅短暂保留；最多显示8个地址，不写系统 hosts、不猜测其他 CDN 域名。

- **测延迟**：测量 TCP 连接与证书验证通过的 TLS 握手总时延，不是 ICMP ping，也不是下载速度。
- **测下载速度**：填写该域名的有效 HTTPS 下载链接。需要鉴权时，可提供 Cookie、User-Agent、Referer、Origin、Authorization 的 JSON 字符串请求头。请求头和链接在界面遮蔽，仅留本次内存，切换域名或关闭窗口即清除，不进入报告。
- **AList 文件择优（v3.3.10）**：打开本机 AList，开启夸克接管，点击此按钮，用 AList 管理员账号登录并选择夸克原视频。仅连接固定的 `127.0.0.1:5244` 元数据接口；支持两步验证码、目录密码和分页，不读取数据库口令或浏览器 Cookie，不修改 AList 设置。管理员取源接口可能需要权限；账号、会话、下载地址和资源请求头仅用于本次内存操作，不进入报告。无需复制签名链接，不转码或降低画质。
- **一键择优（v3.3.10）**：已有手动链接时，刷新并顺序比较同一资源的最多3个 IPv6 候选，优先比较当前 IPv6 网段来源。按本轮有效吞吐样本选择，不把 TLS 延迟当下载速度；成功后显示择优地址和短样本速率。仅作用于相同内容域名的新 HTTPS/443 连接，重新发起播放或下载才能观察，既有连接不打断。
- 下载测速与择优均顺序 Range 请求，每节点最多读取2 MiB响应正文、最多3节点，单节点10秒、整轮35秒，可取消且不能并行叠加。正文最多6 MiB，DNS、请求、TLS、TCP及重传开销另计，非运营商计费上限。实际样本正文计入对应服务 IPv6 统计，不冒充播放内容速率。只接受有效206响应，不跟随重定向；401、403、412或429停止整轮。失败、未测或过期节点不作为相应指标的最快节点。
- 择优结果按域名和物理网络最多记忆5分钟，在内存中保留；DNS到期后在新连接中复核候选，地址移除、网络变化或择优地址连接失败会撤销记忆。失败时只继续其他 IPv6 候选，不回退内容 IPv4。没有记忆时仍沿用原生 IPv6 目标优先策略。成功择优替换该域名原手选记录，后续手选仍优先。记忆到期不后台重新下载测速。
- 没有真实文件链接时，也可以刷新后直接选中一行，点击 **使用所选节点** 立即试用；未测速节点不会被偷偷排除。选择后面板会显示“已选中”，每秒更新 DNS 倒计时不会清掉选中状态。
- 选择 **速度最快优先 / 延迟最低优先** 后点击 **使用最快节点**，或选中一行点击 **使用所选节点**。仅影响该域名之后建立的 HTTPS/443 内容连接，不强制中断现有下载；需要重新发起下载才能观察新选择。
- **恢复自动** 清除该域名手选与择优记忆。选择仅本次会话有效，手选节点过期自动清除；手选节点连接失败时不会偷偷改走IPv4。关闭对应服务会取消正在进行的测试、绕开节点选择并恢复原路径，不影响其他服务。

自动模式遇到临时空 AAAA、解析失败或候选 IPv6 建连失败时，会刷新一次 AAAA，合并解析来源并优先尝试尚未连接过的地址，仍然只使用 IPv6；手动选中的节点失败时只报告失败，不换节点、不回退 IPv4。自动连接、选定节点和探针使用接管前捕获的物理 IPv6 出口，逐套接字指定接口，避免TUN二次嗅探重新选择IP；网卡变化或原出口失效会失败，可全部关闭后重新开启接管。短时测速会受当前网络负载、资源与服务器影响，不保证其他文件或长期下载同样快。HTTPS内容是端到端加密的，助手不能从现有连接自动提取签名下载链接，因此不会假装在没有有效资源链接时完成下载测速。

## 分类开关

五项内容分类启动时默认开启、默认混合；“其他网站”默认关闭，避免误拦不支持 IPv6 的普通页面。主动点击全部开启会将其他网站也限制为 IPv6。每服务的接管开关和混合开关独立，切换结果在底部提示；切换失败只回滚本服务的策略与开关。

顶部每五秒读取本机路由及物理网卡 IPv6 地址，不发送公网测速或探测。有本机出口不等于资源服务器可达；失去 IPv6 时仍保持已选择的内容保护、明确显示不可用，不自动关闭服务或让视频改走 IPv4。主动关闭服务才恢复可能收费的原路径。当前没有公网 IPv6 时，可以验证界面、策略和本机夹具，但不能据此宣布实际 IPv6 下载或 4K 播放验收成功。

- **混合开。** 只有源码明确列出的辅助域名可走原代理/系统解析路径；其中夸克与 B站的完整辅助主机名使用系统 DNS、优先 IPv6 直连，失败时才尝试绑定物理出口的 IPv4，不再经原代理绕行。辅助 IPv4 收发仍扣同一额度并显示为 IPv4；IPv6 辅助不消耗 IPv4 额度。不扩大到整个域名后缀、内容或其他服务，国外辅助仍保留原代理。下载、视频和未知域名仍保持 IPv6，以免产生未授权的收费流量；这不是根据文件大小判断。HTTPS 隧道不能可靠判断文件大小或具体接口用途，“其他网站”不提供混合权限。
- **混合关，即严格 IPv6。** 对识别并接管的该分类请求，包括辅助域名，仅使用 IPv6；没有 AAAA 或连接失败时明确失败，不回退 IPv4。
- **辅助额度。** 混合保护每个服务每次程序启动初始共享 2 MiB 原路径收发额度（上游代理出口未知也扣额度），多连接共同使用；额度耗尽后辅助请求只能尝试 IPv6，失败会提示额度不足，可能影响登录或获取下载链接。点击卡片“补充”并确认后只增加 2 MiB，不清除已用量，也不放开内容 IPv4。不会自动续额，清零、关开服务或重建接管不会补额度。额度按中继流字节，不含 DNS、TCP 重传、协议头等，不能保证运营商计费精确值，也不是整个电脑的 IPv4 防火墙。

混合模式的登录、鉴权、列表等请求可能使用 IPv4。判断大文件或视频走哪种协议，应看内容连接的实际下载量，而不是只看是否存在 IPv6 连接。开关或模式切换会断开该分类已经接管的连接；暂停后继续下载或刷新播放页面，让应用重新连接。开启时必须确认旧原生连接清理，失败仅回滚相关服务，不把其他服务全部关闭。

关闭分类后不再查询内容专用 IPv6 DNS，直接使用原代理；没有原代理时按系统解析优先尝试 IPv4。关闭单分类不会放开其他仍开启分类的 IPv4 限制。接管失效时也允许主动关闭单分类恢复原路径，但重新开启前仍需全部关闭再启动。原代理的最终出口协议不可确认，面板计入“未知”而不是冒充 IPv4 或 IPv6。

v3.3.7 禁止嗅探清除客户端目标，但未覆盖 DNS 映射导致 DIRECT 重新解析的路径。v3.3.8 的专属内核在映射或嗅探分类的 DIRECT TCP 连接中保留已有目标 IP，域名仍用于服务识别与报告，不再用于重选直连服务器。其他服务仍开启时，全机 TUN 仍存在，不能将单分类 DIRECT 描述成物理上完全绕过 TUN；全部关闭才释放接管。开启服务的纯 IP HTTP/HTTPS 连接在中继有界读取 Host/SNI 后原样回放，不解密 TLS、不修改请求签名、Range 或鉴权；无可用域名时仍保留服务上下文，IPv4 目标不会借道已关闭的全局分类。

v3.1.1 修复中继在一端仅关闭发送方向时过早截断响应的问题，并记录传输异常。无 IPv6 地址、IPv6 解析失败和 IPv6 建连失败会分别显示；这些失败不会自动转为 IPv4。软件不解密媒体地址，也不改写带签名的 CDN 链接，不能给没有 IPv6 的内容服务器凭空添加 IPv6。

v3.3.3 进一步修正半关闭连接的生命周期：一端 EOF 后，剩余方向只要持续成功传输就继续保留，连续空闲 30 秒才回收；双向正常打开的连接不新增空闲截止。正常结束、用户切换或退出仍释放中继资源，不通过延长所有连接超时来掩盖停滞。

v3.3.4 对已开启服务的明确辅助域名限制每主机最多 8 个、合计最多 32 个并发会话；超限立即返回带 `Retry-After` 的 503，不继续做上游解析或建连。混合模式辅助原路径连续 3 次建连失败后冷却 15 秒，期间不再尝试该主机上游；冷却自动到期，不需要关开服务。内容连接不使用此辅助限额，关闭服务也不受其限制。报告增加按服务、主机和处理阶段分组及辅助限额状态。该措施不保证客户端遵守重试间隔，也不能单独解决所有入口超时或内核 CPU 异常；IPv4 额度、严格模式和内容 IPv6 路由保持原规则。

v3.1.2 修复中继自身的 IPv6 套接字被 TUN 二次捕获后，内核按嗅探域名重新解析并可能拨 IPv4 的问题。对助手进程的 IPv6 来源连接使用仅 IPv6 出站；判定不依赖嗅探后可能被清空的目标 IP。仍保留客户端域名嗅探，避免原生纯 IP 内容请求丢失平台分类。IPv4 与原代理套接字沿用原路径，不改变单分类关闭恢复策略。此前版本仅凭中继套接字或面板计数不能证明最终出口地址族；该修复也不代表全部视频、夸克文件或播放吞吐已验证。

浏览器视频按 CDN 域名归类，不把整个浏览器都算到某一个网站。Steam / Epic 的本机代理请求还会通过 Windows TCP 连接查询来源进程，用于识别陌生 CDN 和跳转。平台分类不代表每台 CDN 都提供 IPv6，实际以当前连接结果为准。

## Wi-Fi / 有线分流

这个开关**默认关闭，按需手动开启**。启动时只读取当前绑定状态；如果外部已设置 Wi-Fi 绑定，界面会显示实际状态。

根据网卡、路由、权限和本机控制器状态，开启后有两种情况：

- **完整分流**：有线与 Wi-Fi 均已连接且具备路由，并能访问 Clash Verge / Mihomo 本机控制器时，临时调整路由优先级，将普通直连和 `DIRECT` 出站放在有线，将代理节点和提供器绑定 Wi-Fi。通过控制器热重载配置，保留原有节点选择，不改订阅文件；冲突的原有 TUN 在分流期间临时停用。
- **仅 Wi-Fi 绑定**：不满足完整分流条件时，可能只设置内核全局无线接口。**该模式也会影响内核内的 `DIRECT` 连接**，界面会单独标明，不表示已完成有线 / 无线分流。

完整分流关闭或退出时恢复原设置，配置失败会回滚；异常退出有恢复进程处理，未恢复完成的记录会在下次启动时重试。本机恢复记录使用当前 Windows 用户的 DPAPI 加密。**仅 Wi-Fi 绑定需要再次点击开关解除，退出助手不会自动清除它。**

切换后等界面更新，再重新建立连接。其他 VPN、应用自行绑定网卡或更具体的路由也可能影响实际出口。

## 诊断报告

遇到分类异常或连接失败，可以点击**导出报告**，生成 JSON 文件。

报告包含平台和 CDN 域名、各分类流量、网络检测结果和接管状态，以及最近失败的阶段、时间、异常类型和 Socket 错误码。v3.3.1 增加最近 80 条开关、模式、建连地址族、直连对端和失败事件，便于区分切换重连和不同 CDN 连接；不自动换掉正在传输的连接。不包含账号、Cookie、Token、文件内容、文件名、完整下载链接或普通网站域名。助手不安装根证书，也不解密 HTTPS。

v3.3.2 在接管期间使用专用后台线程，每轮间隔 10 秒检查一次本机浏览器代理入口，不测速、不发起外网请求、不检查或修改系统代理所有权。连续三次失败后自动保存 `ingress-*.json` 至 `%LOCALAPPDATA%\IPv6Lens\reports`，每五分钟最多一份，最多保留 20 份入口报告。记录监听器接收进度、待处理请求阶段、线程池及入口 TCP 状态计数，区分 TCP 连接失败与入口无应答；容量拒绝也会单独计数，探针失败不直接判定具体根因。不会因此重启接管、切换节点、断开已有下载或放开内容 IPv4。该探针只证明本机入口能应答，不代表上游、TLS 或实际下载健康；程序退出后不运行。

v3.3.5 在同一独立后台线程增加运行采样，不依赖界面速度刷新：

- 内核占整机 CPU 连续约 30 秒达到 20%，或开启服务一个采样窗口新增至少 10 次失败，自动记录现场。
- 已接收至少 64 KiB、持续存在内容连接，内容速率连续约 60 秒低于 1 MiB/s 时，记录**低吞吐候选**。这不是平台应有网速的保证；HTTPS 不能区分正常暂停、缓冲已满与真正卡顿，因此不把候选当成故障定论。
- 报告保留最多 120 个历史样本，含 IPv4 / IPv6 / 未知速率、失败增量、活动内容数量、内核 CPU / 线程数；触发时补充本机 AList / 爆米花连接状态汇总，不读取媒体链接、文件名或 Cookie。不会为测速下载数据。
- 自动运行报告每五分钟最多一份，保留 20 份 `runtime-*.json`；停止/退出报告另保留 20 份 `automatic-*.json`。保存失败会在界面显示，不再静默丢弃。
- 当前卡顿时可点**记录卡顿**，下次后台采样保存（通常约 10 秒），不必找真实下载链接，不受自动报告五分钟冷却限制，重复点击限频。底部显示待保存、文件名或错误，点击可打开报告目录；导出报告也包含运行历史。

报告功能不会重启网络、切换节点或扩大原路径额度。关闭助手后不继续监测。

公开提交问题时，使用导出的报告和必要截图即可，不要附个人代理配置、订阅链接或原始下载日志。

## 开发与打包

主程序使用 C#、.NET 10 和 WinForms，底层接管使用独立 Mihomo 进程。

在 Windows 11 x64 上准备 .NET 10 SDK、Git、Go 1.24.3 和官方 Mihomo v1.19.10 源码归档。在仓库根目录先构建专属内核，再发布主程序。构建脚本沿用调用进程的代理设置，不修改系统环境或外部代理：

```powershell
./build-core.ps1 -SourceArchive 'C:/path/to/mihomo-v1.19.10-source.zip'
./build.ps1 -Mihomo './work/core-build/mihomo.exe'
```

程序输出到 `app/IPv6Lens.exe`。

`build-core.ps1` 在独立解包目录应用 `third-party/mihomo-original-destination.patch`，加入同目录的 Go helper 与局部测试，测试通过后以 `with_gvisor` 构建 Windows amd64 内核。补丁只调整 DIRECT TCP 的目标地址使用，不改变 DNS 模式、混合额度或服务规则。运行时在开启接管前检查内核版本；不配套时明确失败，不退回旧内核。

原目标与服务开关回归会先将既有物理网卡的本机 IPv4 种入真实 redir-host DNS 映射，再令 DIRECT 解析器返回不同的回环地址，验证最终连接仍到客户端选定的本机服务器，并检查另一服务的 IPv6 流不中断。不启用 TUN、不访问公网、不修改地址或路由：

```powershell
./app/IPv6Lens.exe --takeover-isolation-test 'C:/path/to/existing-folder/isolation.json'
```

界面回归测试只启动本机隔离中继，不修改系统代理、Clash 或网卡配置；输出 JSON 检查结果及深色、浅色、分流、失效和窄窗口截图：

```powershell
./app/IPv6Lens.exe --dashboard-test 'C:/path/to/existing-folder/dashboard'
```

节点择优和本机 AList API 回归使用模拟元数据、内存流和回环服务器，不读取真实账号或发起公网内容下载；两项界面回归输出截图：

```powershell
./app/IPv6Lens.exe --node-optimization-test 'C:/path/to/existing-folder/optimization.json'
./app/IPv6Lens.exe --node-test 'C:/path/to/existing-folder/nodes.json'
./app/IPv6Lens.exe --node-ui-test 'C:/path/to/existing-folder/nodes-ui'
./app/IPv6Lens.exe --alist-resource-ui-test 'C:/path/to/existing-folder/alist-ui'
```

原生出口回归使用本机双栈服务器、DNS 和不启用 TUN 的独立内核，检查最终服务器地址族、DNS 映射、纯 IP 内容分类和 IPv4-only 拒绝：

```powershell
./app/IPv6Lens.exe --native-egress-test 'C:/path/to/existing-folder/egress.json'
```

原代理回环回归仅使用本机服务器和不启用 TUN 的真实内核，以独立代理进程比较旧规则误捕获与修复后的进程豁免，不运行公网下载：

```powershell
./app/IPv6Lens.exe --proxy-bypass-test 'C:/path/to/existing-folder/proxy-bypass.json'
```

完整 HTTPS 链路回归仅使用本机 TLS 源、模拟原代理、DNS 和启用嗅探的隔离内核，分别检查浏览器直达中继、原生接管到中继、辅助原代理与内容 IPv6。此检查不启用 TUN，也不能替代 Windows 实机入口失联的诊断：

```powershell
./app/IPv6Lens.exe --native-pipeline-test 'C:/path/to/existing-folder/pipeline.json'
```

入口取证回归使用本机 IPv6 源及停滞接收夹具，检查自动报告、限频、预请求阶段和既有连接不被打断，不启用 TUN 或更改系统代理：

```powershell
./app/IPv6Lens.exe --ingress-diagnostics-test 'C:/path/to/existing-folder/ingress.json'
```

中继生命周期回归用少量回环字节持续传输超过 30 秒，再检查空闲回收和取消；辅助路径回归模拟故障原代理，检查精确域名例外、实际 IPv4 计量、严格模式、额度及关闭服务后的原路径。可选接口检查需要可用物理 IPv4 网卡，只连接该机自身地址，不访问公网或启用 TUN：

```powershell
./app/IPv6Lens.exe --relay-lifetime-test 'C:/path/to/existing-folder/relay-lifetime.json'
./app/IPv6Lens.exe --auxiliary-route-test 'C:/path/to/existing-folder/auxiliary-route.json'
./app/IPv6Lens.exe --auxiliary-interface-test 'C:/path/to/existing-folder/auxiliary-interface.json'
./app/IPv6Lens.exe --auxiliary-admission-test 'C:/path/to/existing-folder/auxiliary-admission.json'
```
