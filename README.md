# IPv6 下载助手

一个面向 Windows 11 x64 的桌面工具，用来查看下载和视频流量实际经过 IPv6、IPv4 还是未知的代理出口，并按平台选择 IPv6 优先或仅 IPv6 下载。

开发这个工具，是想在校园网下载大文件、看视频时，看清实际使用的协议，让支持 IPv6 的内容服务器尽量走 IPv6。是否免流取决于所在网络的计费规则，使用时可以对照校园网额度记录。

## 界面上的数据怎么看

v3.1.1 主界面按**夸克网盘、Bilibili、Steam、Epic Games、YouTube、其他网站**排列。每张服务卡显示下载速度、上传速度、主要服务器、三色累计下载比例与当前策略：

- **IPv6**：助手通过 IPv6 对外连接时中继的数据。
- **IPv4**：助手通过 IPv4 对外连接时中继的数据。
- **未知**：数据交给了本机原有代理等上游路径，助手无法确认其最终出口是 IPv4 还是 IPv6。本机代理地址为 `127.0.0.1`，不等于远端下载走 IPv4。

顶部圆环汇总六个分类的累计下载。三张流量卡分别显示 IPv6、IPv4、未知的下载速度、上传速度、累计下载、累计上传和最近 60 秒下载趋势。IPv6 下载占比按 `IPv6 下载量 ÷（IPv6 + IPv4 + 未知下载量）` 计算，不含上传。

服务标题右侧的总开关与六张服务卡双向联动，显示全部开启、全部关闭或部分开启。右上方保留**使用说明、详细诊断、导出报告、清零流量**，并提供深色 / 浅色主题切换。窗口缩小时自动切换两列或单列，可滚动查看全部服务。清零同时清除累计量、速率和趋势。

这里统计的是经过助手中继的数据。绕过助手的连接不会计入，因此面板数值不能代替整机流量统计或校园网账单。

## 分类开关

六个分类启动时默认开启，使用两种策略：

- **其他网站：IPv6 优先。** 先尝试 IPv6，目标没有可用 IPv6 或连接失败时，再尝试 IPv4 或原代理。
- **五个下载和视频分类：仅 IPv6。** 对识别并接管的内容连接使用 IPv6；当前内容服务器没有可用 IPv6 时，请求会失败，不回退 IPv4。遇到下载失败或视频卡住，可以关闭对应分类开关，再重新建立连接。

登录、鉴权、列表等请求仍可能使用 IPv4。判断大文件或视频走哪种协议，应看内容连接的实际下载量，而不是只看是否存在 IPv6 连接。切换会断开该分类已经接管的连接；暂停后继续下载或刷新播放页面，让应用重新连接。

关闭分类后不再查询内容专用 IPv6 DNS，直接使用原代理；没有原代理时按系统解析优先尝试 IPv4。关闭单分类不会放开其他仍开启分类的 IPv4 限制。接管失效时也允许主动关闭单分类恢复原路径，但重新开启前仍需全部关闭再启动。原代理的最终出口协议不可确认，面板计入“未知”而不是冒充 IPv4 或 IPv6。

v3.1.1 修复中继在一端仅关闭发送方向时过早截断响应的问题，并记录传输异常。无 IPv6 地址、IPv6 解析失败和 IPv6 建连失败会分别显示；这些失败不会自动转为 IPv4。软件不解密媒体地址，也不改写带签名的 CDN 链接，不能给没有 IPv6 的内容服务器凭空添加 IPv6。

浏览器视频按 CDN 域名归类，不把整个浏览器都算到某一个网站。Steam / Epic 的本机代理请求还会通过 Windows TCP 连接查询来源进程，用于识别陌生 CDN 和跳转。平台分类不代表每台 CDN 都提供 IPv6，实际以当前连接结果为准。

## Wi-Fi / 有线分流

这个开关**默认关闭，按需手动开启**。启动时只读取当前绑定状态；如果外部已设置 Wi-Fi 绑定，界面会显示实际状态。

根据网卡、路由、权限和本机控制器状态，开启后有两种情况：

- **完整分流**：有线与 Wi-Fi 均已连接且具备路由，并能访问 Clash Verge / Mihomo 本机控制器时，临时调整路由优先级，将普通直连和 `DIRECT` 出站放在有线，将代理节点和提供器绑定 Wi-Fi。通过控制器热重载配置，保留原有节点选择，不改订阅文件；冲突的原有 TUN 在分流期间临时停用。
- **仅 Wi-Fi 绑定**：不满足完整分流条件时，可能只设置内核全局无线接口。**该模式也会影响内核内的 `DIRECT` 连接**，界面会单独标明，不表示已完成有线 / 无线分流。

完整分流关闭或退出时恢复原设置，配置失败会回滚；异常退出有恢复进程处理，未恢复完成的记录会在下次启动时重试。本机恢复记录使用当前 Windows 用户的 DPAPI 加密。**仅 Wi-Fi 绑定需要再次点击开关解除，退出助手不会自动清除它。**

切换后等界面更新，再重新建立连接。其他 VPN、应用自行绑定网卡或更具体的路由也可能影响实际出口。

## 诊断报告

遇到分类异常或连接失败，可以点击**导出报告**，生成 JSON 文件。

报告包含平台和 CDN 域名、各分类流量、网络检测结果和接管状态，以及最近失败的阶段、时间、异常类型和 Socket 错误码。不包含账号、Cookie、Token、文件内容、文件名、完整下载链接或普通网站域名。助手不安装根证书，也不解密 HTTPS。

公开提交问题时，使用导出的报告和必要截图即可，不要附个人代理配置、订阅链接或原始下载日志。

## 开发与打包

主程序使用 C#、.NET 10 和 WinForms，底层接管使用独立 Mihomo 进程。

在 Windows 11 x64 上安装 .NET 10 SDK，准备好内核后，在仓库根目录执行：

```powershell
./build.ps1 -Mihomo 'C:/path/to/mihomo.exe'
```

程序输出到 `app/IPv6Lens.exe`。

界面回归测试只启动本机隔离中继，不修改系统代理、Clash 或网卡配置；输出 JSON 检查结果及深色、浅色、分流、失效和窄窗口截图：

```powershell
./app/IPv6Lens.exe --dashboard-test 'C:/path/to/existing-folder/dashboard'
```

制作免安装包：

```powershell
./package.ps1 -Mihomo 'C:/path/to/mihomo.exe' -MihomoSource 'C:/path/to/mihomo-v1.19.10-source.zip'
```

压缩包输出到 `releases/`。打包脚本只收集主程序、图标、内核、说明、许可证和对应版本的 Mihomo 源码归档，不收集本机配置或日志。

第三方组件包括 Mihomo Meta v1.19.10（Windows amd64，GPL-3.0）、YamlDotNet 16.3.0、Microsoft.Diagnostics.Tracing.TraceEvent 3.1.28 和 .NET 10。来源和许可见 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)。
